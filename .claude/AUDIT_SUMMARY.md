## Wave 1 — security & API hardening (commit `e7314e2`)

### P0 — public attack surface

* **R-03** `JWT_SECRET="change-me"` default is gone. The secret is now
  loaded from `JWT_SECRET`, or autogenerated to `~/.stride/jwt_secret`
  in dev. `STRIDE_PRODUCTION=1` refuses to start without an explicit
  secret. (`app/auth.py`)
* **A-001 / R-01 / R-02 / R-04** Every executor endpoint
  (`/api/run-graph`, `/api/run-graph-async`, `/api/execution-plan`,
  `/api/node-types`, `/api/node-definitions`, `/api/converters`,
  `/api/cache/*`, `/api/executions/*/cancel`, `/api/streams/*/frame`)
  now requires `Depends(get_current_user)`. The previously-open
  `/ws/run-graph` WebSocket authenticates via `?token=…` and closes
  with code 4001 on failure.
* **A-002 / R-13** CORS middleware added; allowed origins configurable
  via `STRIDE_CORS_ORIGINS`.
* **A-003 / R-07** New `Content-Length` cap middleware
  (`STRIDE_MAX_BODY_BYTES`, default 16 MiB) plus a 5 MiB Pydantic
  validator on `GraphCreate.data` / `GraphUpdate.data`.

### P1 — DoS / scalability vectors

* **A-004 / S-001** WebSocket bounds concurrent runs per socket via an
  asyncio semaphore (`STRIDE_MAX_WS_CONCURRENT_EXECUTIONS`, default 4).
* **A-005 / A-006** WebSocket messages over `STRIDE_MAX_WS_MESSAGE_BYTES`
  (default 16 MiB) are rejected without closing the socket; invalid
  JSON returns a structured error and the socket survives.
* **R-06** `get_current_user` coerces the JWT `sub` claim through
  `uuid.UUID` so a corrupted token can't trip a SQLAlchemy `DataError`.
* **R-08** Pagination on `GET /api/graphs` (`limit`, `offset`, capped
  at 500).
* **R-09** JWT default expiry reduced from 8 h to 1 h.
* **R-11** `Graph.owner_id` gets `index=True` (PostgreSQL doesn't index
  FK columns automatically).
* **R-12** Migration chain `_build_chain()` is cached at module load
  instead of rebuilt per `migrate()` call.
* **R-10** `datetime.utcnow` → timezone-aware
  `datetime.now(timezone.utc)` for both columns.
* **B-001** Process-global `ExecutionCache` is now an LRU with
  `STRIDE_CACHE_MAX_ENTRIES` (default 1024). Unbounded growth removed.
* **B-002** Cache key is now the full 64-hex-char SHA-256 digest, not
  the prior 16-char truncation.
* **S-002** Streaming `event_queue` is bounded (`STRIDE_EVENT_QUEUE_MAX`,
  default 2048) so a slow consumer applies back-pressure to producers
  instead of growing the buffer to GB-scale.
* **B-010** Deprecated `@app.on_event("startup")` migrated to a lifespan
  context manager.

### Frontend coverage

* New `authFetch()` helper attaches the bearer token; every previously
  unauthenticated `/api/*` call across `App.tsx`, `useGraphExecution`,
  `useNodeLibrary`, `useGraphDependencies`, `useExecutionOrchestrator`
  and `useConverterIndex` now goes through it.
* WebSocket URL carries `?token=…`.
* Exponential backoff + jitter on WS reconnect (was a fixed 2 s loop;
  now 1 s → 30 s with up to 1 s jitter and a deliberate-close flag).
* `writeSession`/`readSession` are quota-safe — private browsing no
  longer crashes the auth screen.

## Wave 2 — plugin & runtime correctness (commit `cbf120b`)

### Plugin packages (PLG findings)

* **PLG-001** Bare `ValueError` / `RuntimeError` in `forward()` replaced
  with `NodeInputError` / `NodeNetworkError` across **stride-yolo,
  stride-rtdetr, stride-mediapipe, stride-clip, stride-grounding-dino,
  stride-depth-anything, stride-pcdet, stride-sam3**. The frontend
  receives a port-attributed error badge instead of the opaque
  `internal_error` code.
* **PLG-002** `fl511.connect` derives a stable `stream_id` from
  `(node_id, camera_id)` instead of a fresh UUID per call. Repeated
  invocation inside a loop reuses the existing ffmpeg + worker threads
  instead of spawning a new bundle every tick.
* **PLG-003** `people.detect` (`DETECT_SPEC`) marked `cache_policy="disabled"`.
  Its background model + tracker update on every frame; an identical
  cloud on the next frame must NOT be served from cache.
* **PLG-004** `ouster.open_source` marked `cache_policy="disabled"`
  (the bundle wraps a live iterator that's torn down at run end) and
  guarded against path traversal via `STRIDE_DATA_ROOT`.
* **PLG-005** MediaPipe task-bundle download raises `NodeNetworkError`
  on timeout/failure instead of bare `RuntimeError`.
* **PLG-006** `stride-traffic` line/polygon/classify counters and
  `SafetyPetAtPolygon` switched to FIFO-capped `OrderedDict`s (4096
  tracks). Long-running deployments no longer accumulate every
  track ID ever seen.
* **PLG-007** `convert.image.from_url` local-file fallback restricted
  to `STRIDE_DATA_ROOT`; user-controlled inputs can no longer
  exfiltrate arbitrary process-readable files.
* **PLG-008** `stride-people` `dbscan_cluster` uses `scipy.cKDTree`
  when available, reducing per-frame cost from O(N²) to O(N log N).
  For a typical OS1-64 frame that's ≈4 B → ≈70 K distance evaluations.

### Backend runtime (B findings)

* **B-004** `CancellationController.mark_abandoned` flags nodes whose
  worker thread was force-abandoned after the interruption deadline;
  `cache_outputs` drops late writes from those threads so they can't
  corrupt the next run's cache.
* **B-005** `node_execution` logs a warning to `ctx.logger` when
  `forward()` returns output keys the spec doesn't declare — surfaces
  spec/impl drift instead of silently trimming.
* **B-008** Loop streaming progress reconciles its pre-reservation on
  early break + a final clamp keeps `total >= completed` so the bar
  can't get stuck below 100% or overshoot.
* **S-003** Per-graph worker cap default lowered from `cpu_count() + 2`
  to 8 (configurable via `STRIDE_MAX_WORKERS`). On a 64-core box this
  caps a single run's threads at 8 instead of 66.

### Type system & shared core (CORE findings)

* **CORE-02** `make_detections2d` stores `image=None` (the canonical
  absent value) instead of `""` for missing images. Downstream
  decoders no longer silently produce garbage on the absent path.
* **CORE-03** `decode_image_bytes` raises `ValueError` on empty input
  instead of silently returning `b""`. Failures now surface adjacent
  to their cause.
* **CORE-04** `NodeSpec.__post_init__` validates `cache_policy` against
  `{"auto", "disabled", "always"}`. Typos fail at import time, not
  at runtime. `NodeExecutor.can_cache` now actually honours the
  field (was previously ignored).
* **CORE-06** `NODE_REGISTRY` reads/writes are serialised by a
  `threading.Lock`. Concurrent plugin imports can't tear the dict
  on alternative runtimes.
* **CORE-07** `t_tuple` subtyping enforces length equality and
  positional assignability (was previously ambiguous with general
  record subtyping).

### Frontend (FE findings)

* **FE-04** `PointCloudMesh` disposes its `BufferGeometry` and
  `ShaderMaterial` on unmount / cloud change. A streaming pipeline
  that produced 30 clouds/s previously leaked 30 VBOs/s into VRAM.
* **FE-05** `runGraphSync` uses the functional `setNodeStatuses(prev =>
  …)` updater so streaming events that arrive mid-flight aren't
  trampled by a stale closure snapshot.
* **FE-06** Undo/redo history strips handler closures from snapshots
  before storing. A 30-node × 50-entry history previously pinned
  ~1500 captured scopes; the new payload is pure data.
* **FE-08** `portTypeFingerprint` memo caches per-node fingerprints by
  the `data` object reference. ReactFlow preserves `data` by reference
  across position-only updates, so drag frames now skip the
  `JSON.stringify` entirely.
* **FE-14** New `isLocked` getter on `useUndoRedo`; wired in `App.tsx`
  via a ref that mirrors `isRunning`. Ctrl-Z no longer yanks the graph
  out from under a streaming execution.

### Ops & deployment polish

* New `/api/health` (liveness, no DB hop, no auth) and `/api/ready`
  (DB ping) endpoints for load-balancer health checks.
* DB connection pool sizing configurable via `STRIDE_DB_POOL_SIZE`,
  `STRIDE_DB_MAX_OVERFLOW`, `STRIDE_DB_POOL_TIMEOUT`.

## Deferred items (with rationale)

* **R-05 (P1)** SQLAlchemy `Session` used in `def` handlers under
  FastAPI. Not a correctness bug — FastAPI runs sync handlers in a
  thread pool — but the new `STRIDE_DB_POOL_SIZE`/`STRIDE_DB_MAX_OVERFLOW`
  config gives operators the right knobs without a full async refactor.
  Migrating to `AsyncSession` everywhere is a separate larger project.

* **CORE-01 (P0 by agent, downgraded)** Duplicate `TypeDescriptor` in
  `app/domain/types.py` vs `stride_core.typesystem.TypeDescriptor`.
  Re-verified: the runtime graph builder uses
  `stride_core.is_assignable_to`; the domain copy is only referenced
  by `app/domain/__init__.py` re-exports and one test module.
  Effectively dead from a correctness standpoint. Deleting it is a
  follow-up cleanup but not urgent.

* **CORE-05 (P1 by agent, intentional)** Source-without-subtype
  rejected by a specific-subtype target. The current behaviour is
  documented as intentional ("specific source flows into generic
  target, not the reverse"). The "no subtype" case is a node-spec
  defect, not a type-system bug; the convert-suggestion UI mitigates
  in practice.

* **B-006 / B-007 (P2)** `_node_status` writes and
  `execution_trace.append` outside `state_lock`. Atomic in CPython
  today; we'd need to revisit if PEP 703 / free-threading lands.

* **S-004 (P2)** Streaming events include full `outputs` dicts; large
  visualisations send the same data twice (once per event, once in
  the final `result`). Splitting into a separate `/api/result/{id}`
  endpoint is a structural change with frontend impact; skipped.

* **FE-01 (P0 by agent, accepted)** Reconnect-closure-staleness risk
  in `useGraphExecution`. The exponential-backoff fix (FE-02)
  incidentally also makes the storm pattern impossible (`onclose`
  schedules at most one reconnect, the `intentionalCloseRef` blocks
  it on unmount). The `connectRef.current` plumbing is no longer the
  highest-leverage change.

* **FE-09 (P1)** Ctrl-C / Ctrl-V keyboard interceptors over custom
  widgets. The current guard checks INPUT/TEXTAREA/SELECT/contentEditable;
  audit found the exposure narrow enough to leave to a follow-up.

* **FE-12 (P2)** Code-split Three.js. Real win (~600 KB off main
  bundle) but invasive to wire React.lazy + Suspense throughout the
  visualiser registry; deferred.

* **PLG-005 (P1, partial)** MediaPipe download uses `urllib.request`
  with a `timeout=120` socket cap. A stalled-but-not-disconnected
  download could still hold the executor thread past that. Wrapping
  in a hard `threading.Timer` deadline is a follow-up; raising
  `NodeNetworkError` on the eventual failure is the immediate fix.

* **PLG-009 (P2)** `requests.HTTPError` `.json()` body parse — already
  guarded by try/except in current code; left alone.

1. Migrate `domain/types.py` callers to `stride_core.typesystem` and
   delete the duplicate (CORE-01 cleanup).
2. Add an end-to-end CI workflow that runs `pytest` + `tsc --noEmit`
   on every PR.
3. Move `runGraphSync` and `useExecutionOrchestrator` to share the
   same `authFetch` helper instead of duplicating the cache-clear
   logic.
4. Add a structured `/api/result/{execution_id}` endpoint so streaming
   events can omit outputs (S-004) — significant bandwidth saving on
   vision graphs.

   ensuring it doesn't outlive the process when reloaders restart.
